# 智慧社区巡检机器人 —— 视觉感知模块

ROS 2 + Gazebo 仿真的小区巡检小车视觉部分：识别**红绿灯**、**人物立牌**、**车牌号**，通过冻结接口发布结果，并对整个街区做人数统计。

- 仿真环境：Ubuntu 24.04 / ROS 2 Jazzy / Gazebo Harmonic（软件渲染）
- 场地：4.2 × 4.2 m 小区，`navigation_frame: map`
- 接口契约：`community_interfaces/msg/PerceptionResult`（v0.1，已冻结）

---

## 一、节点输入输出

| 方向 | 话题 / 消息 | 说明 |
|---|---|---|
| 订阅 | `/camera/image_raw` | Gazebo 相机 RGB 图像（约 1.8 Hz 实际帧率） |
| 订阅 | `/camera/depth` | 深度图（测距备用） |
| 发布 | `/perception/results` | `PerceptionResult`：类别、内容、置信度、包围框 |
| 发布 | `/perception/annotated_image` | 画框 + 名称 + 置信度 + 累计人数，供演示视频与终端一一对应 |
| 终端 | 标准输出 | 按识别顺序打印；人偶按**整个街区**统计输出「检查到社区人员 x 名，非社区人员 y 名」 |

主程序：`perception_node.py`（约 1500 行，单文件无外部依赖，只用到 `cv2` + `numpy`）。

## 二、三项识别的方案

三项共用同一条骨架：**廉价定位 → 归一化 → 判别 → 时间一致性**。

### 1. 红绿灯：位置 + 亮度

先找暗色灯箱（多阈值 V 通道二值化 + 形态学闭运算 + 连通域筛选），再把灯箱横向三等分，取其中**最亮**的一条作为点亮的那颗灯，**按位置**判定红 / 黄 / 绿（左红、中黄、右绿）。

- 判据：最亮条的强彩色像素数 > 阈值，且与次亮条的差要够大（否则说明不止一颗亮着，判为无效灯箱）。
- **刻意不按色相分类红黄**：分辨率低 + 软件渲染下，红与黄的灰度几乎一样，色相判据会把黄灯认成红灯。

### 2. 人偶立牌：多尺度模板匹配（18 张固定贴图）

立牌是 18 张固定贴图（16 居民 + 2 访客），任务本质是"18 选 1"的封闭分类。

**为什么不能用亮度/颜色规则**（实测依据，脚本 `_person_stats.py`，按 alpha 抠出人形后统计前景平均亮度）：

| 类别 | 平均亮度区间 |
|---|---|
| 居民 person_01–16 | 45.1 ~ 148.2 |
| 访客 visitor_1/2 | 43.6 ~ 51.9 |

**访客 F2 = 43.6 是全部 18 张里最暗的一张**，比 15 个居民都暗；访客区间整个落在居民区间的低端**内部**。任何亮度阈值都会同时误判居民与访客。

**实际流程**：

1. 读 A 的素材目录 `community_sim/assets/textures/`，`person_*.png` → `COMMUNITY`、`visitor_*.png` → `NON_COMMUNITY`；类别来自**文件名**，不是图像分类。
2. 每张贴图生成 **14 档尺度模板**：高 `32 × 1.13^i`（i = 0…13），即 32 → 157 px，对应原图 64~314 px。相邻档比例 1.13——v7 用 7 档比例 1.34 时，真实立牌的尺寸常落在两档之间，分数掉到阈值以下导致漏检。
3. 在 **0.5 倍灰度图**上做 `cv2.matchTemplate`（`TM_CCOEFF_NORMED`，零均值归一化互相关）。它先把模板与窗口各自减均值、除标准差，比的是"明暗的排布图案"——**对整体亮度/对比度的线性变化完全免疫**，这正是绕开上面那条死结的关键。
4. 每档取前 10 个响应峰 → 过判据 → 同模板按分数降序、贪心去重 → 每模板保留 **TOP-4**（留 4 个而非 1 个：只留全局最优时，背景里的高分伪峰会把真立牌挤掉）。
5. 全模板候选合并后跑 NMS（IoU > 0.30 或交叠/较小框 > 0.50 视为重复）。
6. 时间一致性投票：同一 `target_id` 要在最近 5 帧中命中 ≥ 3 帧才发布、画框、计数（相机 1.8 Hz，约等于"稳定 1.7 s 才认定"）。

**判据（三条线缺一不可）**：

| 判据 | 阈值 | 依据 |
|---|---|---|
| 相关分 | ≥ 0.65 | 真值最低分 0.655，误检最高分 0.633（车道白线）、0.623（灯杆） |
| 几何 | 原图宽 ≥ 12、高 ≥ 40、长宽比 1.5~6.0 | 贴图实测 2.13~3.84，留足余量 |
| 纹理 | 框内 std ≥ 22、行均值 std ≥ 3、列均值 std ≥ 3 | 见下 |

**纹理判据是用来挡红绿灯杆的**：把误检框打出来发现，灯杆那 14 行**完全相同**（三条竖直色带），竖直方向零变化，行均值 std 只有 0.4；它的相关分 0.709、长宽比 2.31、框内 std 26.6，能骗过当时的所有其他判据。真立牌因为有头 / 肩 / 腿，逐行均值起伏，行均值 std ≥ 5.5（多在 10~30）。列均值 std 同理挡车道白线这类水平条纹。

**全街区统计**：18 张贴图与 18 块立牌一一对应，用 `target_id`（贴图名）当身份 ID 去重；同一块被连续多帧看到只计一次。`ros2 param set /perception reset_counters 1` 可在换检测区时清零重新统计。

### 3. 车牌号：定位 → 摆正 → 切字 → 逐字 OCR

**必须读出字符串**，不能像立牌那样"认出是哪一张"，所以走逐字识别。

1. **定位**：用"一排等高等距横向相邻的**亮笔画**"找车牌，而不是找暗块——车牌底是深藏青（灰度 11~30），但大片黑色路面也暗（13~15），暗块法会把两者连成一片。做法是多组灰度带 (50/58/66/74/82) 并联提亮笔画 → 连通域筛选 → 行聚类（基线 ±0.4 字高 + 横向净间隙 ≤ 2×字高）→ 外扩成板 → 长宽比与框内灰度二次确认。
2. **摆正**：用车牌自身的亮边框定内区，再归一化到官方长宽比 **3.17**（9.5 / 3 cm）。贴图本身是 2.47，被横向拉伸了 1.28 倍，所以字库与实拍必须走同一条归一化路径。
3. **切字**：分位数相对阈值（不用 Otsu——实拍字密 + 渲染模糊，直方图没有干净的谷），丢掉左右边框细条（否则边框会占住第 1 位、整串错位一格），再按连通域裁字修掉 D↔Q、8↔B 的混淆。
4. **识别**：**灰度归一化互相关**，不是二值 IoU。实拍车牌只有 18~19 px 高，二值化后笔画只剩 2~3 px，D 的竖笔与 Q 的尾巴这种差别会被抹掉。匹配时允许 ±3 px 平移 + 宽度三档 (0.88 / 1.0 / 1.12)。
5. **字库双轨**（`plate_glyphs.npz`，65 类 / 128 模板 / 58 KB）：
   - *字体轨*：渲染全字符集（34 省 + 24 字母 + 10 数字），兜底"没见过的车牌"；字体必须横向压扁到车牌字的墨迹宽高比（真实汉字 0.50~0.54、拉丁 0.56~0.59，而系统字体渲染出来是方的 0.69~0.97）。
   - *真字轨*：官方贴图 + 相机原帧里按标签挖出的真字形，逐字置信度可达 1.00。
6. **位次约束**：位 1 只可能是省份汉字、位 2 是字母、位 3–7 是字母或数字（无 I/O），每位在自己的候选池里找最优，低于 `PLATE_MIN_SCORE = 0.45` 输出 `?`。

**离线回归结果**（全部是整图自动定位，不给任何人工框）：相机原帧 6/6 命中、逐字置信度 1.00；旧机位留出帧 3/4（唯一失败的是 0.74 m 外字高仅 9 px 的那块，属物理分辨率极限，工作流是开到 0.4 m 近处拍）；人偶帧零误报。单帧 OCR 约 0.26 s。

## 四、复现步骤

依赖（不在本仓库内，需单独获取）：

- `rbot` —— 机器人本体，基于上游开源项目 [rlxai/rbot](https://github.com/rlxai/rbot) 改造（传感器命名、相机话题）
- `community_sim` —— 队员 A 提供的小区世界包（world + 场景素材）
- `community_interfaces` —— 冻结消息包

```bash
# 1) 环境
export LIBGL_ALWAYS_SOFTWARE=1
export GZ_SIM_SYSTEM_PLUGIN_PATH=$HOME/community_sim/install/community_sim/lib
source ~/rbot/install/setup.bash
source ~/community_sim/install/setup.bash

# 2) 启动小区世界并把小车放进去（用自己的 launch 加载 A 的 world，不改 A 的 world 文件）
ros2 launch rlai_gazebo gazebo.launch.py \
  world:=$HOME/community_sim/install/community_sim/share/community_sim/worlds/community.sdf \
  x:=3.87 y:=3.9 z:=0.1 yaw:=3.14159

# 3) 另开终端，启动感知节点
python3 ~/perception_node.py
# 期望日志：车牌字库: 65 类 / 128 模板

# 4) 看画框图像
ros2 run rqt_image_view rqt_image_view     # 话题选 /perception/annotated_image
```

**离线回归**（不需要 Gazebo，纯用存档图片，改参数前必跑）：

```bash
python3 plate_offline_test.py        # 车牌
python3 person_offline_test.py       # 人偶立牌
```

**常用在线调参**：

```bash
ros2 param set /perception person_min_score 0.62      # 现场漏检时下调
ros2 param set /perception person_min_score 0.68      # 现场零星误检时上调
ros2 param set /perception reset_counters 1           # 换检测区，人数统计清零
ros2 param set /perception plate_dump false           # 关闭车牌复盘存图
```

## 五、已知限制（如实记录）

- 立牌离镜头过近、下半身被画面裁掉时（只剩头肩），整矩形模板匹配会失败 → 巡看保持 0.5 m 以上。
- 立牌尺度下限对应原图 64 px、上限 314 px，超出范围（远景太小 / 贴脸太大）检不到。
- 车牌在 0.74 m 外（字高约 9 px）读不对，属物理分辨率极限，需靠近到 0.4 m 左右。
- 相机安装高度仅 0.125 m，低于灯箱，远距离时灯会跑出画面上缘，红绿灯识别需在较近处触发。
- 若同一张贴图被立在两处，按贴图名去重会算成一个人（可改 `target_id_mode` 退回不去重，但那样无法统计总数）。
